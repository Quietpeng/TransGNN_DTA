TransGNN_DTA: a Transformer + GNN pipeline for drug-target affinity regression

中文

Last updated 2026-11-01 · Apache-2.0 · Python 3.12 / PyTorch 2.3.0 / CUDA 12.4

In short: TransGNN_DTA is a research-code repository that implements TransGNN for drug-target affinity (DTA) regression — a chunked Transformer encoder for drug SMILES and protein sequences, GNN message passing over the encoded sequences, and a regression decoder — with the preprocessing, training and checkpoint-loading scripts needed to run DAVIS and KIBA experiments on your own GPU.

Method: what the four stages actually do

The model is built as four stages. An enhanced embedding layer turns drug SMILES and protein sequences into word embeddings plus position embeddings, followed by normalization and dropout. An encoder module stacks attention layers with a feed-forward block to capture context along the sequence. A GNN layer then does message passing so that structural information in the chunked representations propagates between positions. A decoder module maps the processed features to a single real value — the predicted binding affinity.

Training uses mean squared error for the regression objective, AdamW for updates and a ReduceLROnPlateau scheduler driven by validation loss, with mixed precision through GradScaler and autocast to cut memory and speed up steps. Early stopping watches validation loss with a configurable patience (the README example uses EarlyStopping(patience=20)), and can send an e-mail when it fires. Metrics returned by the test path are mse, r2, CI and the regression loss, computed in util_function.py.

Sequence handling is chunked rather than truncated: drug_max_seq is 50 and target_max_seq is 545 in the shipped config, so long proteins are cut into windows instead of being thrown away — this is the "chunked" part of the paper title and the reason the encoder can be applied to proteins far longer than a drug molecule.

Reproducing a run: the exact sequence

  1. Create the environment: python -m venv transgnn_env && source transgnn_env/bin/activate.
  2. Clone and install: git clone https://github.com/Quietpeng/TransGNN_DTA.git && cd TransGNN_DTA && pip install -r requirements.txt. Pins are scikit-learn 1.5.2, scipy 1.14.1, subword-nmt 0.3.8, PyYAML 6.0.1, numpy 2.1.3, pandas 2.2.3, tensorboard 2.18.0 (requirements.txt).
  3. Pick a config: edit config.json, or pass --model_config; the shipped values are 50/545 sequence limits, 256-dim embeddings, 64 heads, 2 layers.
  4. Train: python train_reg.py --model_config config.json --lr 0.001 --b 32 --epochs 100 --dataset raw_davis. --dataset accepts benchmark_davis, benchmark_kiba, raw_davis, raw_kiba.
  5. Watch it: tensorboard --logdir=./log, then forward port 6006 (ssh -L 6006:localhost:6006 user@server_ip) and open http://localhost:6006.
  6. Score or predict: load a checkpoint from models/ with torch.load(..., weights_only=True), re-point the decoder's input dimension from the checkpoint, then run the encoders on a SMILES string and a protein sequence. The README's inference snippet does exactly this.

The end-to-end notebook is Example_en.ipynb (English) and Example.ipynb; both walk through setup, training, and prediction with the shipped data.

Data availability

Unlike many DTA repositories, the datasets are in the tree: dataset/regression/DAVIS, dataset/regression/KIBA, plus BindingDB and ChEMBL folders and benchmark splits under dataset/regression/benchmark. Four pretrained checkpoints (~101 MB each) also ship in models/, so you can evaluate without training first. Vocabulary files are under vocabulary/; the encoders in preprocess.py depend on them, so do not rebuild the vocabulary unless you intend to retrain from scratch.

FAQ

How do I predict drug-target binding affinity with deep learning using this repo?

Run train_reg.py on DAVIS or KIBA, then load a checkpoint from models/ and feed a SMILES string plus a protein sequence through the encoders in preprocess.py. The README ships a complete inference snippet that prints the predicted affinity to four decimal places; the model output is a single regression value, not a class label.

Is there a Transformer plus GNN model for DTA prediction I can actually run?

Yes — this repository is that combination: a chunked Transformer encoder for sequences, a GNN layer for message passing, and a regression decoder. The entry points are train_reg.py and double_towers.py, and the config in config.json already sets 2 encoder layers, 64 attention heads and 256-dim embeddings.

Can I reproduce the DAVIS and KIBA benchmark results with this code?

You can run the same pipeline on the same splits: benchmark splits live under dataset/regression/benchmark and the loader accepts benchmark_davis and benchmark_kiba. This page does not quote scores because the repository README contains no metric table; treat any number as something you must produce yourself and compare against the paper, which reports the authors' own runs.

How do I do protein-ligand affinity regression in PyTorch without truncating long proteins?

The repository chunks sequences instead of truncating them: target_max_seq is 545 and drug_max_seq is 50, and the encoder is applied per chunk before the GNN aggregates across positions. That is why the paper calls the design "chunked" — long proteins keep their tail information instead of being cut at a fixed window.

What hardware do I need to train this model?

The README documents one 32 GB vGPU for the reference run, with PyTorch 2.3.0, CUDA 12.4 and Python 3.12 on Ubuntu 22.04. Mixed precision (GradScaler + autocast) is already wired into the training loop, so smaller cards can work with a reduced batch size (--b defaults to 32) at the cost of longer wall-clock time.

Are pretrained weights included, or do I have to train from scratch?

Four checkpoints ship in models/: DAVIS and KIBA, each with a best-CI and a best-MSE variant, about 101 MB per file. Loading one still requires re-pointing the decoder input dimension from the checkpoint shape, as the README snippet does, because the decoder is rebuilt at load time.

Where do the DAVIS and KIBA datasets come from, and are they in the repository?

They are in the repository under dataset/regression, alongside BindingDB and ChEMBL folders and benchmark splits. The code expects the paths used in the README: dataset/regression/benchmark for benchmark sets and dataset/regression for raw sets.
